# Служба поддержки студентов

Мини-проект №8 по дисциплине «Парадигмы программирования» (PP 2205, СРО 2).
Очередь заявок, приоритеты, история статусов, контроль SLA и отчёты.
Python 3.9+, только стандартная библиотека.

## Запуск

```bash
python main.py --demo        # готовый демонстрационный сценарий
python main.py               # интерактивное консольное меню
python main.py --generate    # пересоздать data/tickets.json
python -m helpdesk.prototype # императивный прототип (лекция 2)
python -m unittest discover -s tests -t .   # тесты (61 шт.)
```

Момент отчёта по умолчанию фиксирован (`22.10.2026 12:00`), поэтому результаты
воспроизводимы. Другое время: `python main.py --now 2026-10-25T09:00`.

## Что умеет

| Пункт меню | Действие |
|---|---|
| 1 | Очередь обработки (по приоритету, затем по сроку SLA), «!» — SLA нарушен |
| 2 | Список нарушений SLA с величиной просрочки |
| 3 | Статистика: статусы, приоритеты, % соблюдения SLA, среднее время решения |
| 4 | Регистрация новой заявки |
| 5 | Смена статуса (показываются только допустимые переходы) |
| 6 | История статусов заявки |
| 7 | Смена политики приоритета (пересчёт сроков всех заявок) |
| 8 | Сравнение политик «Обычный период» и «Экзаменационная сессия» |
| 9 | Сравнение трёх парадигм на одной задаче |

Статусы: Новая → В работе ⇄ Ожидает студента → Решена → Закрыта
(из «Решена» можно вернуться в «В работе»; из «Закрыта» переходов нет).
Приоритеты: P1 Critical (4 ч), P2 High (8 ч), P3 Normal (24 ч), P4 Low (72 ч).

## Структура

```
main.py                  точка входа, меню и демо
helpdesk/
  models.py              Status, Priority, Ticket, TicketView, исключения
  policies.py            PriorityPolicy, DefaultPriority, ExamPeriodPriority
  analytics.py           чистые функции над TicketView
  pipeline.py            замыкания, генератор очереди, map/filter/reduce
  service.py             HelpDesk — хранение заявок и команды
  data.py                генератор данных, JSON, build_desk
  reports.py             текстовые отчёты и сравнение политик
  prototype.py           императивный прототип
  paradigms.py           три решения одной задачи + замеры
data/tickets.json        30 заявок (результат generate_records, seed=2026)
tests/                   61 тест (unittest)
docs/                    отчёт и презентация
```

## Распределение тем лекций 1–8

| Лекция | Где реализовано |
|---|---|
| 1. Парадигмы | `paradigms.py`: императивное, объектное и функциональное решения одной задачи, сверка и замер |
| 2. Императивная | `prototype.py`: переменные, накопление состояния, `if`, `for` |
| 3. Процедурная | Функции с явными параметрами: `analytics.py`, `pipeline.py`, `reports.py`, `data.py` (более 30 функций) |
| 4. Модули | Данные/модели (`models.py`, `data.py`), логика (`service.py`, `analytics.py`, ...), точка входа (`main.py`) |
| 5. ООП | `Ticket` (закрытое состояние, свойства, проверка переходов), `HelpDesk` |
| 6. Интерфейсы | `PriorityPolicy` → `DefaultPriority`, `ExamPeriodPriority`; композиция: политика-обёртка и `HelpDesk` «имеет» политику |
| 7. Функциональная | Чистые функции `is_overdue`, `open_queue`, `sla_compliance`, ...; `TicketView` неизменяем; рекурсия: `raise_priority`, `reachable` |
| 8. Высший порядок | Замыкания `category_is`, `priority_at_least`, `overdue_at`; `iter_queue` (генератор на куче); `map`/`filter`/`reduce` |

## Данные

`data/tickets.json` — 30 заявок за последние 4 суток с историей статусов.
Файл создаётся функцией `generate_records(n=30, seed=2026)`; при одинаковом
`seed` набор одинаков (проверяется тестом).
